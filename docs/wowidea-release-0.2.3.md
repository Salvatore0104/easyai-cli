# 0.2.3：异步图片结果恢复与自动下载

本版本修复“网站任务已成功，但 Codex 没有返回图片”。根因不是图片 CDN 路径，而是生成 POST 超过 CLI 原 30 秒请求时限后仍在网站完成；CLI 没拿到 taskId，而线上 `GET /v1/tasks?idempotencyKey=...` 又未实际过滤或返回幂等键，导致无法继续轮询和下载。

- 图片提交等待上限提高到 120 秒，视频为 60 秒；超时或断网后最多继续 90 秒只读恢复，绝不再次 POST。
- 提交前记录账号任务快照。旧服务器忽略幂等过滤时，只接受时间、媒体类型匹配且唯一的新增任务；零个或多个候选都保持 uncertain。
- `image generate`、`video generate` 默认轮询并下载，返回 `taskId`、`status`、绝对 `paths` 和 `pointsUsage`。`--no-wait` 仅用于明确的后台提交。
- 支持 `data.task.result` 等常见包裹结构；任务先成功、结果 URL 稍后落库时继续查询同一任务，不会重新生成。
- CDN 下载遇到临时网络或 TLS 错误时最多重试 3 次；重试仅限结果文件 GET，绝不重提付费生成。

自动化测试覆盖唯一快照差分恢复、多个候选拒绝、媒体类型不符、过旧任务、进程重启不重投、嵌套响应、默认异步轮询下载、实际积分和绝对输出路径。线上只读验证使用既有成功任务完成状态查询和下载，没有新增付费任务。

后端仍需合并 OpenAPI overlay：生成 POST 应快速返回 `202 + taskId`；任务列表必须真正按 `idempotencyKey` 过滤，未知键返回空列表，并对账号与请求 payload 实施原子幂等唯一约束。CLI 快照差分只是旧服务兼容措施。
